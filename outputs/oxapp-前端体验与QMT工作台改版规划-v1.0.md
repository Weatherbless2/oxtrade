# oxApp 前端体验与 QMT 工作台改版规划 v1.0

## 1. 规划结论

当前 oxApp 已经完成了“登录后通过正式 HP-Socket 查询 PostgreSQL 中的 QMT 最新行情”的第一条真实链路，但前端仍停留在技术验证型行情表格：首屏只有一张表，缺少市场概览、行情详情、数据新鲜度、异常反馈和清晰的业务层次；表格交替行和边框对比度过高，导致界面突兀，交互反馈也不够完整。

后续必须把前端体验作为独立交付主线，与 QMT 业务接口和实时行情链路并行推进。用户最终看到的应是一个可以浏览、筛选、查看详情、理解数据来源和感知连接状态的行情工作台，而不是“数据库查询结果展示器”。

## 2. 当前状态与目标状态

| 方面 | 当前状态 | 目标状态 |
| --- | --- | --- |
| 数据来源 | 正式 HP-Socket -> C++ -> LBM/Worker -> PostgreSQL `ta_data` | 保持正式链路，页面明确标识来源和时间 |
| 数据范围 | 最新股票和期货行情，共约 6080 条 | 按市场、资产类别、关键词和状态浏览全部数据 |
| 页面结构 | 顶部导航 + 左栏 + 中央单表 + 右侧配置 | 概览区、筛选区、表格区、详情区、状态栏五层信息结构 |
| 交互 | 基础筛选、分页、刷新 | 快速筛选、列管理、排序、行详情、复制、收藏预留、错误恢复 |
| 状态 | 成功/失败文字较弱 | 加载中、空数据、无权限、过期、断线、重连、查询失败均可理解和恢复 |
| 实时性 | 数据库快照查询已通 | 接入 `OX-P1-01` 后显示 Push 连接、序列号、延迟和实时更新 |
| 视觉 | 深蓝基础主题，但表格白色交替行过亮 | 统一蓝灰层级、低对比边界、明确焦点和告警色 |

## 3. 设计原则

1. 数据真实性优先。没有历史 K 线或实时 Push 数据时，显示清晰的“暂未接入”状态，不绘制虚假曲线、不伪造实时变化。
2. 业务层级优先。先让用户知道当前市场、数据更新时间、连接状态和总量，再查看具体记录。
3. 高频操作少打断。筛选、翻页、刷新、查看详情不使用阻塞对话框；错误在当前工作区内联展示，并提供重试。
4. 状态可解释。所有数据都显示来源、行情时间、入库时间和新鲜度；不能只显示一个“成功”。
5. 视觉统一。颜色、间距、圆角、字体和控件高度通过主题 token 统一，禁止页面各自定义一套颜色。
6. 低频页面与行情页面分离。行情实时更新不进入 Query Worker 或低频 IPC；管理类页面继续走正式查询链路。

## 4. 前端改版工单

### OX-UX-01：工作台视觉设计系统

**目标**：解决截图中左右区域和表格对比度过高、控件风格不统一的问题。

**实现内容**：

- 建立背景、面板、浮层、边界、主文字、辅助文字、成功、警告、错误、涨跌等主题 token。
- 深色主题使用蓝黑分层，不再使用刺眼的白色交替行；表格行采用轻微层差和悬停/选中反馈。
- 统一 4/8/12/16/24 间距、6px 圆角、控件高度和标题层级。
- 统一按钮语义：刷新、收起、展开、重试、查看详情使用图标和 tooltip；明确动作保留图标+文字。
- 统一表头、分页器、空状态、加载状态和错误提示样式。
- 右侧配置面板与中央工作区使用同一背景体系，只用一条低对比边界区分区域。

**不做**：不修改 QMT 数据协议，不增加数据库表，不制作装饰性渐变和无业务意义的图形。

**验收**：登录页、行情页、右侧面板、状态栏在深色主题下无刺眼白块；浅色主题仍可读；所有主按钮有 hover、pressed、disabled 状态。

### OX-UX-02：登录与会话体验

**目标**：让用户清楚知道登录是否成功、连接到哪里以及登录后的工作区为何可用。

**实现内容**：

- 登录窗口保持非全屏，默认尺寸适合桌面，最大化由用户主动触发。
- 账号、密码、登录按钮提供明确的聚焦、提交中、失败和重试状态。
- 登录成功后展示用户、Session 摘要和服务连接状态，不展示密码或敏感凭据。
- 登录后自动进入工作台首页或上次允许访问的页面；无权限菜单明确置灰或隐藏并给出原因。
- 退出登录清理会话展示，避免旧行情或旧账号信息残留。

**验收**：成功、错误密码、断线、超时、权限不足和注销均有可理解反馈，Qt 主线程不被阻塞。

### OX-UX-03：QMT 行情工作台信息架构

**目标**：把当前单一行情表升级为可扫描、可比较的业务工作台。

**目标布局**：

```text
行情中心
├── 工作台摘要栏
│   ├── 股票数量 / 期货数量
│   ├── 当前筛选结果 / 全量总数
│   ├── 最近入库时间 / 数据新鲜度
│   └── HP-Socket、数据库连接状态
├── 市场与资产筛选
│   ├── 全市场、0、1、2、D、F、H、Z、I、G
│   ├── 股票 / 期货 / 债券 / 回购等资产类别
│   ├── 代码或名称搜索
│   └── 排序、刷新、列显示设置
├── 行情列表
│   ├── 代码、名称、资产类别、市场
│   ├── 最新价、昨收、涨跌、成交量、成交额
│   ├── 行情时间、入库时间、来源
│   └── 分页、每页数量、总数和加载状态
├── 行详情抽屉或详情面板
│   ├── 主数据字段
│   ├── 最新行情字段
│   ├── 数据源与时间字段
│   └── 该标的可用业务操作
└── 底部状态栏
    ├── 当前用户与 Session 摘要
    ├── 连接状态
    ├── 当前页 / 总页数
    └── 最近刷新时间与错误提示
```

**业务规则**：

- `Y` 只表示深沪京业务集合 `0 + 1 + 2`，界面同时保留 0、1、2 的独立筛选。
- `D/F/H/Z/I/G` 只表示六个期货市场，不按股票交易所解释。
- `9` 为 NEEQ，日历来源显示 QMT 不支持时使用的官方补充来源；不能静默混入 `Y`。
- `stkinfo`、`ft_stkinfo`、`stkprice`、`ft_stkprice` 的字段在 UI 中分别标注主数据或最新行情。

### OX-UX-04：详情、筛选和可理解反馈

**目标**：让用户不仅能看表，还能理解一行数据为什么是这个值。

**实现内容**：

- 点击行打开详情抽屉，表格保持上下文不丢失。
- 详情中区分“证券主数据”“最新行情”“数据时间”“来源”和“可用操作”。
- 搜索结果显示匹配条件；清空筛选后恢复全市场。
- 筛选、排序和翻页请求显示轻量加载状态，旧响应不能覆盖新筛选结果。
- 空结果显示“没有匹配数据”和清除筛选入口；服务失败显示错误码摘要和重试入口；无权限显示所需权限。
- 时间字段统一使用中国时区展示，区分 `quote_time` 与 `receive_time`。

### OX-UX-05：实时行情 Push 用户体验

**前置**：`OX-P1-01` 实时订阅、广播、序列号和慢客户端策略完成。

**实现内容**：

- 页面显示“快照模式 / 实时模式”，避免用户误以为数据库快照就是实时 Push。
- 显示订阅标的数、最近 Push 时间、序列号、延迟、断档和重连状态。
- 对更新行做短暂、低干扰的涨跌反馈；采用批量刷新或节流，不逐 Tick 重绘整张表。
- 断线时保留最后一份数据，但明确标记为“数据可能过期”；恢复后显示恢复时间。
- 慢客户端或消息丢弃只在状态栏和日志中给出可定位提示，不阻塞用户操作。

**架构边界**：

```text
QMT 回调 -> oxMWH 标准化/去重/序列号 -> HP-Socket Push
-> Python Transport -> AsyncQtBridge -> 行情页批量刷新
```

该链路不经过 Query Worker、System V 低频队列或 PostgreSQL 慢查询。

### OX-UX-06：业务页面统一体验

**目标**：让系统管理、权限、产品资金和风控页面与行情工作台拥有同一套交互语言。

**实现内容**：

- `lbm_sys`：字典、菜单、服务状态、运行日志使用统一列表/详情/状态组件。
- `lbm_right`：用户、角色、站点、菜单权限显示权限范围、状态和审计信息。
- `lbm_fund`：产品、资产、资金账户、关联关系使用摘要卡片 + 表格 + 详情布局。
- 风控：参数、规则、事件区分配置状态、启停状态和后端最终校验结果。
- 所有页面统一支持加载中、空数据、无权限、失败、重试和分页。
- 页面不直连数据库、不调用 LBM；只调用 Service 和 Transport 抽象。

        +--> OX-P0-13 QMT 市场/主数据/日历/IPO 业务接口

        |        +--> OX-UX-03 行情工作台信息架构
        |        +--> OX-UX-04 详情、筛选和反馈

                 |

## 6. 每个工单的交付门禁

每个前端工单完成后必须产出一份简明 Markdown，至少写清楚：

| 内容 | 必须说明 |
| --- | --- |
| 做了什么 | 用户能直接看到的变化 |
| 技术实现 | PySide6 组件、Service、Transport、Qt Bridge、线程边界 |
| 业务逻辑 | 市场代码、数据来源、筛选、权限和状态规则 |
| 架构图 | 输入、处理、输出和不在范围的模块 |
| 代码位置 | 具体文件、类、函数和关键注释 |
| 验收结果 | 正常、空、错误、无权限、断线和恢复状态 |
| 未完成项 | 不把快照、Mock 或占位能力写成实时生产能力 |

## 7. 最终用户体验验收

用户登录后应能完成以下完整流程：

1. 看到账号、连接状态和数据来源。
2. 在全市场、股票市场和六个期货市场之间切换。
3. 看到真实总量、当前结果数、更新时间和数据新鲜度。
4. 使用代码/名称筛选、排序、分页和刷新。
5. 点击一行查看主数据、行情数据、来源和时间。
6. 遇到空结果、权限不足、服务失败或断线时知道原因并能恢复。
7. 实时 Push 完成后，看到明确的实时模式、延迟、重连和数据过期状态。
8. 切换主题、收起左侧菜单和右侧配置面板时，内容不跳动、不丢失筛选和选中状态。

## 8. 当前明确不做

- 第一阶段不实现交易、下单、撤单和真实资金变更。
- 不把没有数据源支持的历史 K 线、Tick 图表画成真实图表。
- 不在 Qt 页面中直接连接 PostgreSQL 或调用 LBM。
- 不把 QMT 最新快照查询描述为实时 Push。
- 不为了视觉效果新增不符合 QMT 核心表范围的数据库表。

`OX-UX-01` 高保真原型已完成，文件为 `outputs/oxapp-frontend-prototype-v2.html`，交互和映射说明见 `outputs/oxapp-OX-UX-01原型说明.md`。当前进入原型评审门禁：确认目标布局、低对比视觉、详情区、状态栏和快照/实时边界后，再修改 PySide6 主题、行情工作台和详情交互。代码修改应从当前正式认证/QMT 基线创建独立前端体验分支，避免把视觉改动和未完成的实时 Push 混在同一个工单中。

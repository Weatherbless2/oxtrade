# OX-P0-12 阶段说明：真实全市场行情工作台

## 用户会看到什么

正式模式下，行情中心默认是“全市场行情”，不是一两条演示数据。用户可选择股票交易所或六个期货市场、输入代码/名称、使用上一页/下一页浏览真实查询结果。表格显示标的、名称、股票/期货类型、最新价、行情时间、入库时间和 `QMT/PG` 来源；顶部状态会显示总条数和当前页数量。

```text
全市场筛选 -> Qt 页面 -> HP-Socket -> Worker -> lbm_qmt.so -> ta_data -> Qt 表格
```

## 这次做了什么

- 去掉正式页面默认硬编码单标的，默认请求全市场分页。
- 增加市场范围和关键词筛选，支持沪深北与六个期货市场。
- 真实结果新增股票/期货类型字段，页面只显示已有真实 PG 数据能力。
- 正式模式隐藏尚未实现的实时订阅、Tick、K 线和盘口，避免把空功能当作可用功能。

## 验收

本地 C++ `20/20`、Python `14/14` 通过。

## 当前真实展示的阻塞

Windows PostgreSQL 当前只监听 Windows 回环地址，WSL 后端无法访问 `5432`，所以还不能在这台 WSL 环境中启动服务并截取真实全量数据页面。不是数据缺失，QMT/PG 的表和此前真实查询证据仍在；是 WSL 到 Windows PostgreSQL 的网络可达性问题。

## 面试讲法

“我把正式行情页改造成服务端分页的全市场工作台。页面只通过 HP-Socket 请求，后端由 `lbm_qmt.so` 查询 PG；前端展示市场范围、股票/期货类型、来源和入库时间，正式模式不回退 Mock。数据库不可达时我保留明确失败态，不用演示数据覆盖真实联调问题。”
